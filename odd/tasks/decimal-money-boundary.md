# Decimal money boundary — arithmetic exact end-to-end
Objective: guarantee exact money arithmetic end-to-end (Postgres Decimal(18,2) → domain cents via money module → number at the API edge), eliminating silent float drift. Branch: `feat/sale-readiness-hardening` (continue). Delivery: `ask-on-risk`, feature-branch-chain. Runner: vitest with disposable PG fixture `postgresql://postgres@127.0.0.1:54497/accountexpress_test?schema=public` (never the ambient DB). User authorization (verbatim): "no, primero soluciona de punta a punta este problema, luego vamos a sanear los amarillos y los rojos pendientes del analisis anterior, te parece?".

## Specs
S1. Money module `src/lib/money.ts`: cent-based primitives (toCents/fromCents/sum/compare/maxAbs), built on `Prisma.Decimal` (existing dependency — no new packages), rounding convention ROUND_HALF_UP (half-away-from-zero) documented in the module header, and a SAFE-RANGE GUARD: any money value whose cent representation exceeds |2^53-1| cents (≈ $90.07 trillion) throws a descriptive error instead of drifting silently.
S2. `src/lib/db.ts` result-layer coercion becomes exact and consistent: Decimal→number only after the cents-range check (throw on unsafe magnitude), and the SAME conversion rule applies to findMany/groupBy/aggregate results (fixing the type inconsistency where aggregates returned Decimal while findMany returned number).
S3. Ledger-critical arithmetic converts to cents via the money module: `JournalEntryService.recalculateBalance` (no float sums, no float writes — validate exact posting against Decimal reference), account balance aggregation in `src/app/api/accounts/route.ts` (getAccumulatedBalance/directBalance), `src/lib/services/closing-engine.ts`, `src/lib/services/journal-correction.service.ts` balance math, and apply-all engines' money math. Exactness tests compare each site against a Decimal.js reference on adversarial fixtures (0.1-style rows, 1000-row sums, mixed signs).
S4. API/UI contract unchanged: money fields keep arriving as `number` (exact at cent level for realistic magnitudes; unrealistic magnitudes fail loudly). Document the invariant in the money module header and `docs/`: ALL money arithmetic MUST go through `src/lib/money.ts`; raw `+`/`-` on money fields is forbidden.
S5. No behavior change for valid data: all existing money-related suites stay green (journal, correction, accounts, reports, backups fidelity) and report/dashboard outputs match previous values on fixtures.
